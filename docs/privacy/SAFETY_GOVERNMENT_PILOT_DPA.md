# Government pilot data-processing agreement schedule

Status: reviewable schedule, not an executed contract. Both parties and counsel
must fill and approve the following before real personal-data processing.

| Required field | Approval/evidence required |
|---|---|
| Parties/controller/processor | Legal names, representatives and actual contacts |
| Purpose and lawful authority | Specific permitted safety purpose and jurisdiction |
| Data subjects and classes | Citizens, witnesses, victims/minors; minimize fields |
| Access | OAuth issuer/audience/client scopes, resource grants, mTLS requirement |
| Subprocessors/locations | Approved providers, processing regions, cross-border basis |
| Retention and holds | Approved periods, legal-hold authority, storage/backup procedure |
| Subject rights | Intake, verification, response owner, correction/removal exceptions |
| Security | Independent assessment, encryption/access controls, export audit, incident procedure |
| Incident notice | Agreed contact, timing and escalation responsibilities |
| Exit | Revocation, export minimization, deletion/retention attestation |

Pilot technical acceptance requires applied migration SHA, configured gateway,
two-person publication/AAL2/RLS evidence, byte verifier evidence, signed APK/AAB,
SBOM/provenance, physical tests and restore drill. Code existence does not execute
this agreement or demonstrate partner adoption. Real FIU data requires a
separate tenant and agreement outside the public application.
