## 1. Proprietary Terminal PTY/TTY & Termux Architecture
### Problem & Discovery
- Interactive CLI tools like Google Antigravity (`agy`), interactive Python REPLs, top/htop, and POSIX utilities expect an interactive pseudo-terminal (`/dev/pts/*`, `isatty(0) == true`).
- On Android 14/15/16 (SDK 34/35), SELinux restrictions and W^X memory protections prevent standard execution from `/data/data/.../files` without explicit PTY emulation.

### Solution
- **Native PRoot & PTS Emulation**: Integrated `libproot.so` inside `LocalShellManager.kt` with `/dev/pts` bind mounts.
- **POSIX Script Subshell Wrapping**: Executions wrap interactive calls through `script -qec "<command>" /dev/null` or dedicated pty allocations.
- **Termux Command Suite & AGY Upstream**: Upgraded system execution to Antigravity CLI upstream (`agy --version 1.1.16`) and battery/device status telemetry bridge (`termux-battery-status`).

## 3. High-Reliability ECU Connection & RFCOMM Clean Release
### Root Cause of Reconnection Friction
1. **Socket Collision**: Android's Bluetooth stack held RFCOMM channels in cooldown if closed asynchronously without buffer flushing.
2. **Destructive Reset (`ATZ`) & Protocol Flooding**: A 1.5s timeout on initial sync triggered hard resets and broad 20-protocol sweeps, causing automotive ECUs (K-Line / CAN) to enter bus-off silent protection.

### Architectural Solution
- **Persistent ECU Fingerprint (`AdapterFingerprint.kt` & `KnownGoodAdapterStore`)**:
  - Persists `ObdProtocol`, `ecuHeader` (`ATSH`), `initCommands` (`ATIB10`, etc.), `recipeId`, clone state, and vehicle `vin`.
  - Dual-indexed by adapter MAC address and vehicle VIN.
- **Dedicated Fast-Path Sync (`ElmNegotiator.kt`)**:
  - Eliminates hard resets on reconnect; applies memorized protocol and header immediately.
  - Grants up to 3 focused probe attempts with 4500ms timeout specifically to the vehicle's proven ECU parameters.
- **Clean RFCOMM Teardown (`BtClassicTransport.kt`)**:
  - Performs synchronous stream flushing, socket teardown, and a 120ms release delay on disconnect.
  - Prioritizes the proven connection method (`Insecure Reflection CH1`) at the head of the connection queue.

## 4. Garage Physical ECU VIN Reading & Permanent Binding
### Implementation
- **Dedicated Action Button in Garage**: Prominent `⚡ LEER VIN (OBD-II ECU FÍSICA)` button added to each vehicle card in `GarageScreen.kt`.
- **Multi-Protocol Dealer-Grade Query Sequence (`ObdSession.kt`)**:
  1. Standard OBD-II Mode 09 PID 02 (`0902`) with ISO 15765-2 multi-frame reconstruction.
  2. UDS Diagnostic DID `22F190` (Manufacturer VIN identifier).
  3. KWP2000 / OEM Service `1A90` (Read ECU Identification).
  4. Enhanced Mode `2100` / `2101`.
  5. Dedicated CAN Header probing (`ATSH 7E0`, `ATSH 7DF`, `ATSH 18DAF110`).
- **Permanent Vehicle & Cloud Binding**:
  - Automatically updates the vehicle's `vin` field in SQLite/Room (`VehicleDao`) and pushes the upsert to Supabase (`cloud_vehicles`).
  - Binds the physical adapter fingerprint to the vehicle's VIN in `AdapterFingerprint`.
  - Instantly updates the UI card to `VIN: <VIN> [ECU]`.
