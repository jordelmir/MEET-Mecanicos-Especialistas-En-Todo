## 1. Overview & Architecture

This release unifies the **Repair Network**, **Tow Services**, **Parts Marketplace**, and **Universal Services** under a single server-authoritative **Service Platform Kernel**, reusing the high-performance geospatial infrastructure of **Viajes** across all verticals.

Simultaneously, this release resolves core OBD/ECU link instability and accelerates post-clear DTC verification by introducing targeted validation (`DiagnosticScanMode.CLEAR_VERIFY`), reducing clear verification latency from >15s to <1.5s while preserving 100% forensic evidence integrity.

## 2. Key Deliverables

### Track 1: Service Platform V2 & Repair Network
1. **Universal Service Platform Kernel (`ServicePlatformKernel.kt`)**:
   - `ServiceActor`: Typed roles (`CUSTOMER`, `TECHNICIAN`, `WORKSHOP_MANAGER`, `TOW_OPERATOR`, `PARTS_STORE`, `SERVICE_PROVIDER`, `PLATFORM_ADMIN`) with strict permission checking (`ServicePermission`).
   - `Money`: Exact minor units (ISO-4217) for CRC (0 decimals), USD (2 decimals), and EUR (2 decimals), replacing floating-point `Double`.
   - `ServiceCommandEnvelope`: Signature-capable envelope model and idempotency key specification for Supabase RPC commands.
2. **Common Map Infrastructure (`CommonMapKit.kt` & `CommonMapAdapters.kt`)**:
   - `RideMapAdapter`, `RepairMapAdapter`, `TowMapAdapter`, `PartsMapAdapter`, `UniversalServiceMapAdapter`.
   - Consistent MapLibre rendering, pin styling, route tracing, and camera controls.
3. **State Transition Engines**:
   - `RepairStateEngine.kt`: Server-authoritative repair lifecycle with role and evidence guards.
   - `TowStateEngine.kt`: Complete towing lifecycle (`REQUESTED` → `MATCHING` → `ASSIGNED` → `EN_ROUTE` → `ARRIVED` → `LOADING` → `LOADED` → `IN_TRANSIT` → `ARRIVED_DESTINATION` → `UNLOADING` → `DELIVERED` → `COMPLETED`).
   - `PartsStateEngine.kt`: Fitment verification matrix across 5 tiers (`EXACT`, `HIGH`, `PROBABLE`, `INSUFFICIENT_DATA`, `CONFLICTED`).
4. **Dimensional Reputation & Rating (`ServiceRatingV2.kt`)**:
   - 6-dimension evaluation restricted to verified transactions with closed work orders.
5. **Zero Demo Actors Enforced by CI**:
   - Eradicated `mechanic_101`, `driver_101`, `store_101`, and demo phone numbers.
   - Protected by `ProductionHardcodedActorGuardTest.kt`.

### Track 2: OBD/ECU Link Stability & Fast Clear
1. **Typed Transport Exceptions (`TransportExceptions.kt`)**:
   - `TransportReadFailure`, `TransportRemoteClosed`, `TransportWriteFailure`, `TransportConnectTimeout`, `AdapterNoPrompt`, `EcuNoResponse`.
2. **Hardened Transports (`BtClassicTransport.kt` & `BleTransport.kt`)**:
   - Unconditional `cancelDiscovery()` before SPP connection.
   - Immediate exception propagation in `read()` upon socket closure.
   - Asynchronous CCCD notification confirmation (`onDescriptorWrite`) in BLE.
3. **Known-Good Adapter Store & Fast Reconnect Path (`AdapterLinkProfile.kt` & `ElmNegotiator.kt`)**:
   - Caching of connection method, RFCOMM channel, and protocol for instant reconnects.
   - Three-tier recovery: Fast Path → Warm Recovery (`AT WS`) → Full Discovery (`AT Z`).
4. **Centralized Connection Supervisor (`ConnectionSupervisor.kt`)**:
   - Mutex-guarded lifecycle eliminating race conditions on transport switching.
   - Real-time `ConnectionHealth` scoring.
5. **Targeted DTC Clear Verification (`DiagnosticScanMode.CLEAR_VERIFY`)**:
   - Post-clear verification queries only target ECUs/namespaces in the `ClearVerificationPlan`.
   - Drastic reduction in clear operation latency.
