# ELYSIUM MOBILITY OS — SECURITY MODEL SPECIFICATION
**Status**: AUTHORITATIVE SPECIFICATION V1  
**Baseline SHA**: `2f3b4535d8fc9c82d4d718217afe73ab28b65a2c`  
**Governing Rule**: *Assume hostile clients. The Android app is NEVER a trusted security boundary. Authorization is strictly server-enforced.*

---

## 1. Security Architecture Principles

1. **Zero Client Trust**: The server treats all client payloads as unverified proposals until validated against database invariants and cryptographically bound identities.
2. **Actor-Bound Storage Predicates**:
   - Passenger actions evaluate: `WHERE id = p_request_id AND passenger_id = auth.uid()`
   - Driver actions evaluate: `WHERE id = p_request_id AND assigned_driver_id = auth.uid()`
   - Admin actions require: `has_role('RIDE_ADMIN')` verified against server roles table.
3. **Fail-Closed Identity**: Missing or ambiguous session tokens immediately terminate the transaction with `UNAUTHENTICATED`. No anonymous fallbacks or `"SYSTEM"` impersonations.
4. **Idempotency & Replay Resistance**: Every state mutation requires an `idempotency_key` (16-128 chars) bound to `auth.uid()`. Retrying with identical payload returns the cached result; retrying with mismatched payload fails with `IDEMPOTENCY_MISMATCH`.

## 2. Row-Level Security (RLS) Policy Architecture

### `public.ride_requests`
```sql
ALTER TABLE public.ride_requests ENABLE ROW LEVEL SECURITY;

-- Passengers can view their own requests
CREATE POLICY ride_requests_passenger_select ON public.ride_requests
    FOR SELECT TO authenticated
    USING (passenger_id = auth.uid());

-- Assigned drivers can view their assigned trips
CREATE POLICY ride_requests_driver_select ON public.ride_requests
    FOR SELECT TO authenticated
    USING (assigned_driver_id = auth.uid());

-- Active verified drivers can discover SEARCHING requests within their jurisdiction
CREATE POLICY ride_requests_discovery_select ON public.ride_requests
    FOR SELECT TO authenticated
    USING (
        state IN ('SEARCHING', 'OFFERED') AND
        EXISTS (
            SELECT 1 FROM public.ride_driver_vehicles v
            WHERE v.driver_id = auth.uid() AND v.is_active AND v.verification_status = 'VERIFIED'
        )
    );

-- Direct client UPDATE/DELETE is completely forbidden; mutations must use RPCs
CREATE POLICY ride_requests_prevent_direct_update ON public.ride_requests
    FOR UPDATE TO authenticated USING (false);

CREATE POLICY ride_requests_prevent_direct_delete ON public.ride_requests
    FOR DELETE TO authenticated USING (false);
```

### `public.ride_offers`
```sql
ALTER TABLE public.ride_offers ENABLE ROW LEVEL SECURITY;

-- Passenger can view offers submitted for their ride
CREATE POLICY ride_offers_passenger_select ON public.ride_offers
    FOR SELECT TO authenticated
    USING (
        EXISTS (
            SELECT 1 FROM public.ride_requests r
            WHERE r.id = request_id AND r.passenger_id = auth.uid()
        )
    );

-- Driver can view their own submitted offers
CREATE POLICY ride_offers_driver_select ON public.ride_offers
    FOR SELECT TO authenticated
    USING (driver_id = auth.uid());
```

## 3. Cryptographic Controls & Sensitive Evidence

1. **Boarding PIN Verification**:
   - The passenger receives a 4-digit PIN generated by `ride_issue_boarding_pin_v2`.
   - The server stores only `boarding_pin_hash = sha256(p_pin || salt || trip_id)`.
   - The driver enters the 4-digit PIN physically; the server hashes and compares. Exact PIN is never transmitted to driver or exposed in realtime channels.
2. **Location Breadcrumb Encryption**:
   - The Android `RideLocationTrackingService` encrypts raw coordinates with `DeviceMessageCipher` (AES-256-GCM) before buffering in local SQLite.
   - WorkManager delivers the encrypted payload.
   - PostGIS converts to `GEOGRAPHY(POINT, 4326)` server-side under authenticated RPC `ride_record_location_breadcrumb_v2`.
3. **Evidence Storage Isolation**:
   - Driver verification documents, identity cards, Dekra inspections, and criminal record certificates are uploaded exclusively to Supabase private storage bucket `trust-verification-evidence`.
   - Access requires short-lived signed URLs generated only for authorized Trust Center reviewers with MFA authentication.
